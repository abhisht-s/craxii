# Stage 21 native macOS client decision

Status: accepted for V0.0.01 Stage 21.

- The client is a native macOS 14 SwiftUI application with narrowly used AppKit lifecycle hooks. A checked-in Xcode project contains app, unit-test, and UI-test targets; a local Swift 6 package contains `CraxiiProtocol ← CraxiiClientCore ← CraxiiAppleAdapters`. There are no external Swift dependencies, backend-internal DTOs, provider DTOs, WebKit wrappers, or cross-platform UI frameworks.
- One opaque 64-lowercase-hex device token is stored only as a Security.framework generic-password item. Its service is `com.craxii.device-token.v1`, its account is the immutable backend-profile UUID, and its accessibility is `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`; it has no access group or synchronization. A 401 does not delete it, and malformed stored material remains for explicit repair.
- Local storage is disposable, atomically replaced, owner-only, and limited to nonsecret backend profile/namespace metadata, the last applied durable cursor, and a bounded exact-material command outbox. Canonical messages, Work, drafts, socket state, credentials, and authorization headers never persist. Corrupt cache is quarantined; corrupt outbox material is never sent.
- Message and cancellation intent receives a fresh UUIDv7 before persistence. The exact path, canonical JSON body, `Idempotency-Key`, command ID, material hash, profile/Craxii/credential generation binding, and attempt count are saved before the first send. Ambiguous retryable failures receive at most three total attempts with unchanged material; relaunch bootstraps and reconciles before resending.
- Bootstrap atomically replaces the memory projection and establishes the authoritative snapshot cursor. The client then reconciles the outbox, opens `GET /v1/events?after=<cursor>`, applies durable replay, waits for the current connection generation's `sync.complete`, and only then accepts live drafts. Cursor advances and persists only after successful decode, validation, and reduction; unknown durable types do not advance it and receive one fresh-bootstrap recovery path.
- One `ClientSession` actor owns profile/credential generation, HTTP commands, projection, outbox, cursor, WebSocket generation, receive/ping tasks, reconnect, and lifecycle state. Superseded-generation callbacks are ignored. Reconnect uses bounded full jitter, clears every draft, retains only the last applied durable cursor, and never fabricates backend state.
- Durable public events alone mutate canonical projection. Bootstrap `conversation_sequence` orders snapshot messages; later public messages retain durable application order because live events do not expose that sequence. Server message IDs and client/work correlation IDs enforce deduplication and conflict detection. Public tool projection is deliberately limited to safe IDs, optional name, status/result class, outcome flag, and timestamps.
- Drafts occupy a separate generation-local map. Start is required before deltas; duplicate/regressive sequences are ignored, gaps are accepted, and text/refusal remain separate. Abandonment, terminal Work, authoritative assistant commit, disconnect, reconnect, sleep, shutdown, and relaunch discard drafts. Drafts are never concatenated into committed messages or persisted.
- The app surface is a diagnostic shell for endpoint, credential status/actions, connection state, safe identities/cursor/counts/errors, and explicit connect/reset. Stage 22 exclusively owns transcript, composer, navigation, rich tool/draft rendering, cancellation controls, production styling, onboarding, and polished error UX.
