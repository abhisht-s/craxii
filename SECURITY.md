# Security policy

Craxii is pre-alpha and is not production-ready. Security fixes are considered for the current `main` branch and for any pre-release version explicitly identified as supported when published. Older commits and unlisted builds are not supported versions.

## Reporting a vulnerability

Do not disclose suspected vulnerabilities in a normal public issue, pull request, discussion, or social-media post.

Use GitHub private vulnerability reporting for this repository once that repository feature is enabled. If the private reporting option is not visible, avoid publishing details and use the GitHub profile of a project maintainer to request a private reporting channel.

A useful report includes:

- the affected commit or published version;
- operating system and relevant environment details;
- the likely impact and affected boundary;
- minimal reproduction steps;
- a minimal proof of concept or redacted logs with credentials and private content removed; and
- a suggested mitigation, if one is available.

The project will acknowledge, triage, and provide updates on a best-effort basis. There is no fixed response-time promise, remediation SLA, or vulnerability bounty. Where appropriate, please coordinate public disclosure until a fix or safe mitigation is available.

Do not send working credentials, private keys, personal data, or unrelated proprietary material with a report.
